# نظام تقييم MIDAD

تم تنفيذ مسارات REST التالية:

- `GET /api/orders/:orderId/rating-context`
- `POST /api/reviews`
- `GET /api/products/:productId/reviews`

يعتمد النظام على الطلبات ذات الحالة `approved` باعتبارها الطلبات المكتملة/المدفوعة في التدفق الحالي. يمنع القيد الفريد على `reviews.order_id` التقييم المكرر على مستوى قاعدة البيانات، بينما يتحقق الراوتر من التكرار قبل الإدراج ويتعامل مع سباق الطلبات عبر خطأ التعارض الفريد.

لا يقبل إنشاء التقييم إلا `order_id` و`rating` و`comment`؛ الحقول الزائدة مرفوضة. تُنسخ `full_name` و`product_id` من الطلب الموجود في قاعدة البيانات ولا تُقرأ من جسم طلب العميل. لا يعيد سياق التقييم رقم الهاتف، ولا يعيد endpoint العام للتقييمات إلا الاسم والتقييم والتعليق وتاريخ الإنشاء، مع التصفية على `is_visible = 1`.

## ملاحظة أمنية حول order_id

المخطط الحالي يستخدم `purchase_requests.id` كعدد صحيح داخلي متزايد، ولذلك فهو ليس معرفاً عشوائياً غير قابل للتخمين. لم يتم تغييره في هذه المرحلة حتى لا تنكسر الطلبات والروابط القائمة. قبل الإنتاج العام، ينبغي إضافة `public_review_token` عشوائي عالي الإنتروبيا إلى جدول الطلبات، أو إنشاء جدول public order access tokens، واستخدامه في رابط التقييم مع إبقاء `order_id` مرجعاً داخلياً فقط. يجب تخزين الرمز بصيغة hash أو حمايته كسرّ وصول، وإبطاله عند الحاجة، مع استمرار التحقق من حالة الطلب والتقييم الفريد.
